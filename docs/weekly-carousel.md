# 공연 달력과 주간 캐러셀

2026-11-16 구현 초안. 기준은 `codex/instagram-unified-integration`의 `b265717`이며 main이 아니다. 사용자가 업데이트 후 실제 Google 로그인 성공을 확인했다. 구현 단계에서는 운영 배포와 실제 Instagram 게시를 실행하지 않았으며, 이후 사용자 요청에 따라 아래 운영 배포를 완료했다.

## 사용하는 방법

1. 허용된 Google 계정으로 로그인하고 **인스타그램 → 공연 달력**을 연다.
2. **공연 등록**에서 공연명·장소·실제 회차를 입력하고 포스터를 선택한다. 회차는 한 줄에 `2026-11-16 19:30` 또는 `2026-11-22` 형식이다. 날짜만 알면 시간을 비워 둔다. 기간 전체를 매일 공연으로 추정하지 않는다.
3. 기존 인스타그램 자료는 **기존 인스타 게시물에서 등록**으로 선택한다. 캡션은 원문에 보관하며 공연 날짜로 게시 날짜를 사용하지 않는다. 가져오기에 실패하면 수동 포스터 업로드를 사용한다. 같은 게시물 이미지의 중복 등록은 거부하고 기존 공연을 연다.
4. 정보 확인 상태를 **정보 확인 완료**로 저장한다. 가격 미확인은 카드에서 생략하며 무료와 구분한다. 공연 클릭으로 수정·숨김·삭제가 가능하다. 저장한 주간 카드가 참조하는 공연은 삭제 대신 숨김을 사용한다. 인스타그램 원본 게시물은 수정하지 않는다.
5. 별도의 **인스타그램 → 주간 디자인** 메뉴에서 주를 선택하고 공연을 최대 8개 고른다. 주 시작은 한국 시간 월요일이며 제목은 그 월의 월요일 순번이다. `2026-11-16~22`는 `2026년 11월 셋째 주 공연`이다. 월말 주는 월요일이 속한 달로 이름 붙인다.
6. 카드의 위로/아래로 버튼 또는 끌기로 순서를 바꾸고 제목·일시·장소·가격 표시문을 편집한다. 표지 제목·부제·뒷표지 문구와 캡션도 편집 가능하다. **초안 저장**은 서버에 저장하며 다른 기기에서도 목록에서 다시 열 수 있다.
7. **이미지 미리보기**로 실제 1080×1350 JPEG를 확인한다. 이미지를 클릭하면 원본 크기로 볼 수 있다. 개별 JPEG 또는 JPEG와 caption.txt를 담은 ZIP을 내려받는다. 포스터는 전체를 비율 유지로 배치한다. 너무 긴 문구는 잘라내지 않고 축약 편집을 요청한다.
8. **게시 전 최종 확인**은 이미지·순서·캡션·계정을 고정한다. 여기까지 Meta 미디어 컨테이너를 생성하거나 공개 게시하지 않는다. 전체 내용과 계정을 확인하고 체크한 뒤 **확인한 내용 지금 게시**를 눌러야 게시한다.
9. 미디어 처리 중에는 확인 후 **확인한 게시 처리 계속**을 사용한다. 응답이 불명확하면 **게시 상태 확인**만 사용한다. 게시 완료 시 ID와 조회 가능한 경우 원문 링크를 보관한다. 준비 완료/실패 단계의 **초안 다시 편집**은 이전 게시 작업을 원자적으로 취소한 뒤 새 버전으로 연다. 발행 처리 중/결과 불명확/완료 상태는 다시 편집할 수 없다.

동일 주의 복수 초안은 허용하지만 이미 게시 작업이 있으면 경고한다. 동일 초안의 중복 클릭은 서버가 합치며, 다른 초안으로 의도적으로 다시 게시하는 것까지 막지는 않는다. 날짜 확인 필요 공연은 별도 목록에 있고 해당 주 후보에는 나타나지 않는다. 카드용 문구 수정은 원본 공연 데이터를 덮어쓰지 않는다.

## 저장과 구조

- UI는 기존 `index.html`의 해시 기반 CSP를 유지한다. 렌더·미리보기·다운로드·전송은 같은 JPEG 바이트를 사용한다. 새 외부 라이브러리나 인증 방식을 추가하지 않는다.
- `/api/weekly`는 기존 세션/Google 인증, 허용 계정과 출처 검사를 통과한 POST만 받는다. 현재의 허용 직원 계정 모두를 관리자로 취급하며 별도 권한 체계는 추가하지 않는다.
- `cloudflare/src/weekly.mjs`가 `INSTAGRAM_JOBS` 바인딩의 `weekly-library` 명명 객체를 사용한다. 새 바인딩·마이그레이션·유료 서비스는 없다. 공연/초안의 버전 검사는 다른 창의 오래된 저장을 409로 거부한다.
- 공연 자료와 초안은 자동 만료하지 않는다. 포스터는 긴 변 최대 2000px, 최대 2MiB JPEG로 정규화해 비공개로 저장한다. 원본 파일 자체의 백업은 아니다. 교체·삭제 후 공연이나 저장 카드가 참조하지 않는 포스터는 정리한다.
- 공연과 주간 초안은 각각 최대 1,000개이다. 첫 버전은 작은 운영 규모를 대상으로 전체 목록을 조회한다. 대규모 이력은 추후 페이지 처리/보관 정책이 필요하며 Cloudflare 계정의 실제 저장·요청 한도는 별도 적용된다.
- 기존 게시용 Durable Object를 캐러셀로 확장한다. 하위 컨테이너 생성·상태 조회 후 최종 캐러셀 컨테이너를 발행한다. `posting` 상태를 원격 발행 전에 영구 저장하고 불명확한 결과는 자동 재발행하지 않는다.
- 카드 수는 표지·뒷표지 포함 3~10장으로 보수적으로 제한하며 공연은 최대 8개이다. JPEG 1장 최대 4MiB, 합계 최대 10MiB로 기존 요청 크기 제한을 유지한다. 이는 앱의 초기 상한이며 Instagram 앱의 최대 장수와 동일하다는 의미가 아니다. 운영 전 해당 계정/API의 지원 상태를 확인한다.
- 게시용 이미지 URL은 기존 방식으로 준비 후 최대 24시간 제공한다. URL을 아는 사람은 만료 전 열람 가능하다. 편집 자료와 확정 JPEG 사본은 인증 API를 통해서만 제공한다. 작은 캐러셀 작업 영수증은 만료하지 않아 이미지 삭제 후에도 중복 방지 상태를 유지한다. 기존 단일 이미지·예약 게시의 보관 정책은 유지한다.
- 준비 중 연결 실패로 작업이 생성되지 않았으면 예약한 작업 ID를 해제한다. 편집 잠금 해제와 게시 시작은 동일 작업의 원자적 상태 검사를 사용한다. 장기 발행 이력에는 확정 캡션·카드·JPEG·계정·게시 ID·상태를 유지한다.

## 이번 범위와 확인 경계

- 기본 보라색 테마는 검토용 1종이다. 브랜드 로고 파일을 임의로 만들지 않고 ENTICKET 문자 표기를 사용했다. 최종 디자인은 담당자가 실제 포스터로 확인한다.
- 주간 화면 진입 시 한국 시간의 현재 주를 제안한다. 백그라운드 월요일 자동 생성, 캐러셀 예약 게시, 무인 게시, 자동 발행 재시도는 없다. 기존 단일 이미지 예약 기능은 유지한다.
- 실제 공연 자료를 임의로 이관하지 않았다. 11월 공연 몇 건으로 내용 검수와 디자인 검토가 필요하다. 기존 게시물의 캐러셀은 이미지별로 선택하며 동영상은 가져오지 않는다. 한 포스터에 여러 공연이 있으면 별도 수동 등록으로 나눌 수 있다.
- 실제 Meta 읽기/캐러셀 게시 권한은 이번에 운영 계정으로 재검증하지 않았다. 과거 문서의 접근 차단 기록은 현재 장애로 단정하지 않는다. API 접근이 불가해도 수동 등록·이미지 제작·다운로드가 가능하다.
- 실제 Instagram 게시는 별도의 사용자 내용 확인 후 수행한다. 로그인 연장 정책, 전체 기기 로그아웃, 요청 횟수 제한과 직인 기능은 변경하지 않았다.

## 달력 정리와 날짜 자동 가져오기 (2026-11-16)

- 월 제목·오늘 표시·공연/회차 집계, 확인 상태 색상과 포스터/공연명/시간 카드로 달력을 정리했다. 모바일에서는 작은 포스터 대신 공연명과 시간을 우선한다.
- **인스타에서 가져오기**는 최근 12개 게시물에서 공연을 찾아 포스터와 원문을 저장하고, 캡션에 명시된 실제 공연 날짜로 달력에 배치한다. **이전 게시물도 가져오기**로 다음 묶음을 가져온다. 새 공연이 현재 달 밖에만 있으면 해당 달로 이동한다.
- 날짜 추출은 규칙 기반이며 AI 호출이나 게시 시각/현재 연도 추정은 하지 않는다. 일시/일정/공연일/달력 이모지 항목의 명시적인 연월일, 이어지는 회차 날짜, 오전/오후 또는 24시간 표기를 처리한다. 예매 오픈/접수/마감은 공연일에서 제외한다.
- 연도 누락, 기간 범위, 잘못된 날짜/요일과 축약된 여러 날짜는 자동 배치하지 않고 날짜 확인 필요로 저장한다. 오전/오후가 없는 `7시`는 날짜만 배치하고 시간을 비워 둔다. 자동 등록한 공연은 정보 확인 필요 상태이며, 게시 전 내용 확인이 필요하다.
- 같은 게시물은 다시 가져와도 건너뛰며 수정한 데이터를 덮어쓰지 않는다. 동영상과 공연으로 식별되지 않는 게시물은 제외한다. 여러 이미지의 게시물은 공연이 여러 개일 수 있어 별도 확인 대상으로 표시한다. 이미지 실패는 다른 공연의 가져오기를 중단하지 않으며 해당 항목에서 다시 확인한다.
